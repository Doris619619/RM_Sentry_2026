# 第三阶段交接

当前可用能力：实际场地图形、真实点云、地图对齐、真值定位、手动控制和现有规划器的路径展示。
当前未通过项：多项式段间连续性，详见 KNOWN_ISSUES.md；先修复并重跑 15 个实景案例。

按以下顺序推进，不直接打开生产启动组合：

1. 修复时长/系数同步问题，确认位置和速度连续性、端点、静态占据检查全部通过。
2. 对齐跟踪器输入：/global_trajectory 为 map 多项式，定位 twist 为 base_link，速度转换只能做一次。
3. 在独立仿真入口接入现有跟踪器和速度桥接，禁止键盘与控制器同时发布 /cmd_vel。
4. 默认低速运行，保留 0.5 m/s、0.5 rad/s 限幅、0.5 秒真实时间 watchdog 和暂停恢复清零。
5. 分开测试轨迹丢失、定位丢失、点云 TF 缺失、节点崩溃、急停和目标不可达，不把路径显示当成运动通过。
6. 先验证短直线、横移、90° 转向后的机体系速度，再验证五组场景内路径跟踪、停车距离与到点误差。
7. 重新测量 Gazebo + RViz + MPC 全链路至少五分钟的实时率和资源占用；本阶段性能不能外推到完整导航。
8. 若需要真实碰撞、坡道、多层场地或定位精度验收，必须引入相应动力学、模型与传感器标定，不沿用当前简化模型的声明。

模型与地图：保留当前 0.05 米分辨率和地图原点，换图后重做哈希、地标、自由区域及点云对齐检查。
阶段一和阶段二入口均作为回退路径保留，生产入口、MCU 和硬件驱动仍不参与。
