# 轨迹修复与验收

用户在发现问题后明确授权“有问题就修复”。原参考轨迹在最后一次可行性检查或总时长压缩后
使用旧系数，造成 9/15 次段间跳变；仅同步系数后仍测到 8.03 m/s² 的加速度超限。

最终实现按三次多项式每段两端检查加速度理论峰值，调整时长后重求系数，至多 64 次。
只有时长不再变化且系数有限才输出；无效输入或未收敛时清空全部输出，由原规划管理器报告失败。
单段没有相邻段时不访问越界元素，保留实际初速度与停止终速度边界。
不再将物理时长压缩到 30 秒；参考位置/速度显示按相同时间网格最多 600 点并包含终点。
控制端应按 TrajectoryPoly 的 duration 采样，不能把显示列表误当固定 0.05 秒控制序列。

回归：四种失败在旧实现复现；最终 8/8 C++ 测试通过。
实际 Gazebo 五组各三次 15/15 通过，最大检查点间距 0.019421 m，
端点误差小于 0.000001 m，占据区样本为 0，最大加速度 3.977958 <4 m/s²，
根据速度平方导数实根求极值，最大速度 2.31728 <2.5 m/s。
消息结构、源地图、跟踪核心未修改；此结果不包含自动跟踪或自动到点。

证据：evidence/feasibility-tests.xml、fixed-planning-summary.json 和 planning-cases.json。
修复前数据保留在 planning-cases-before-fix.json；中间仅同步系数版本保留在 planning-cases-timing-only.json。
