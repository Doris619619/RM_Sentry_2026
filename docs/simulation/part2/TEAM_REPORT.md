# 第二阶段队会汇报（五页）

## 第 1 页：阶段目标与当前结论

标题：自己的地图场景已经接通真实点云和现有规划器

讲述：在第一阶段手动运动和真值定位基础上，实现“打开场地—手动移动—看点云对齐—RViz 点目标—看规划结果”。
机器人仍由键盘控制，没有自动跟踪、自动到点或真实定位。
本次场地是二维占据轮廓的简化挤出，不能作为比赛场地三维复原或碰撞动力学验收。

结论：地图、点云和路径展示已通过阶段验收。修复后五组各三次 15/15 通过；下一阶段接入跟踪前，先统一参考速度与底盘限速。

## 第 2 页：系统链路

~~~text
Gazebo 场地 + 机器人
  ├─ 真值状态 → 速度安全适配 → /localization/odometry + TF
  └─ gpu_lidar → bridge → /sim/lidar/points
                        → 过滤、测量时刻 TF → /filted_topic_3d + /aligned_points

原地图 + 真值定位 + 点云 + RViz /goal → 现有规划器
                                  → TrajectoryPoly + 原有 Marker → RViz
键盘 → 超时、限幅保护 → Gazebo 运动（没有自动跟踪）
~~~

讲述：ROS domain 26，统一仿真时间，缺少对应时刻 TF 就丢帧。
使用真实传感器回波，地图显示不是点云来源。没有同时启动 fixture、HDL、Point-LIO 或 MCU。

## 第 4 页：现场演示与实测指标

播放 demo.mp4（89.8 秒），或按 README 现场启动：

## 第 5 页：问题与下一步

已经解决：最初 9/15 次段间跳变；继续检查发现加速度约 8.03 m/s² 超过配置 4。
修复时长与系数同步、按每段理论峰值迭代到可行，不再为显示点数压缩物理时长。
最终 15/15 通过，最大加速度 3.978 m/s²，段间误差小于 0.000001 m，8 项 C++ 回归通过。
RViz 改为 Qt 主线程先停绘制再清理 ROS，连续三轮及长时间运行后的退出均正常。

仍需关注：保留 GLSL、EGL、Qt 和 MINCO 警告，生产全链测试在最小 overlay 中缺少 decision_node，
不把这些记录写成全部通过。当前参考速度约 2.32 m/s，高于仿真命令保护的 0.5 m/s。

第三阶段：统一速度坐标和轨迹时长/限速关系，验证控制权切换、停车、暂停恢复、计算负载和到点判据。
详细清单见 HANDOFF.md。
